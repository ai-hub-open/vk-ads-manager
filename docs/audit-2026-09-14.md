## Дефекты

### 1. 🔴 Скрипты падают на Windows-консоли — `UnicodeEncodeError`

13 из 14 CLI-скриптов не запускаются в стандартной консоли Windows: `sys.stdout` там `cp1252`/`cp866`, а весь вывод и argparse-help написаны кириллицей.

```
python -m scripts.forecast --help
UnicodeEncodeError: 'charmap' codec can't encode characters in position 58-64
```

Воспроизводится на `--help` и на любом `print()`. С `PYTHONIOENCODING=utf-8` всё работает. Лечится строкой, которая **уже есть** в `upload_creatives_to_storage.py:180` (единственный скрипт, который не упал):

```python
if sys.platform == "win32":
    sys.stdout.reconfigure(encoding="utf-8")
    sys.stderr.reconfigure(encoding="utf-8")
```

**Правка:** вынести в общий хелпер (`scripts/_console.py` или в `credentials.py`) и вызвать в начале `main()` всех 20 скриптов с кириллицей в выводе. Приоритет высший: у скилла Windows — основная среда маркетолога, а сейчас первая же команда из SKILL.md падает трейсбеком.

**✅ Исправлено в 0.6.6.** Добавлен `scripts/_console.py`; `setup_console()` стоит первой строкой `main()` во всех 16 точках входа, в `install.py` логика продублирована (он запускается до распаковки скилла). Проверено на консоли `cp1252` без `PYTHONIOENCODING`: все 16 скриптов отвечают на `--help`, `forecast.py` проходит полный цикл, прямой запуск `python scripts/X.py` тоже работает (фолбек импорта).

### 3. 🟠 Не описан способ подключения, которым скилл реально подключают

Вся документация (`references/vk-ads-mcp-integration.md`, `docs/hosted-mcp-setup.md`, `setup_vk_ads_mcp.py`) знает только форму `https://vkads-mcp.aihub.click.ru/mcp` + заголовки `X-Click-Ru-*`. Сервер поддерживает и **персональную ссылку подключения** `https://vkads-mcp.aihub.click.ru/o/<connection-id>/<token>` (проверено: `initialize` и `tools/list` отвечают, суффикс `/mcp` не обязателен). Для claude.ai и коннекторов Claude Desktop это единственный рабочий способ — произвольные заголовки они передавать не умеют.

**✅ Исправлено в 0.6.6.** Раздел «Коннектор по персональной ссылке» в `docs/hosted-mcp-setup.md` (с предупреждением, что ссылка равнозначна паролю к кабинету), четвёртая строка в таблице «Авторизация» в `references/vk-ads-mcp-integration.md`, флаг `--connection-url` в `setup_vk_ads_mcp.py` (env `VK_ADS_CONNECTION_URL`): пишет запись без блока `headers`, токен в выводе маскируется, мусорную ссылку отклоняет. Регрессия по трём старым путям авторизации (click.ru, готовый токен, `--remove`) прогнана.

### 4. 🟡 `priced_event_type` описан неполно

`references/vk-ads-mcp-integration.md` утверждает: `0 = CPM, 1 = CPC, 30 = oCPM`. Для `site_conversions` так и есть, но у `leadads` оба активных пакета (3215, 4618) приходят с `priced_event_type: 51`.

**Правка:** дописать `51` (оплата за лид, лид-формы) и снять формулировку «модель оплаты определяется этими тремя значениями» — значений больше, ориентироваться надо на имя пакета (`_cpm_`/`_cpc_`/`_ocpm_`) и на `available_objectives`.

**✅ Исправлено в 0.6.6.**

### 5. 🟡 Неверное обоснование, зачем нужен `ad_groups_get`

Дока: «исключение — `vk_ads_ad_groups_get`, он удобен тем, что отдаёт `issues`». Проверено на группе 150765736: `issues` приходит **только** при явном `fields=…,issues`, и `campaigns_get` отдаёт их ровно так же. Без `fields` оба возвращают три поля.

**Правка:** заменить абзац на «`issues` доступны и в `campaigns_get`, и в `ad_groups_get`, но только при явном `fields="…,issues"`; по умолчанию оба отдают `id`, `name`, `package_id`». Иначе агент вызовет `ad_groups_get` без `fields`, не увидит `issues` и решит, что с группой всё в порядке.

**✅ Исправлено в 0.6.6.**

### 6. 🟡 Не описан конверт ответа статистики

Шаг 9.5 велит взять фактические CPM/CTR из `vk_ads_statistics_summary`, но раздел «Конверт ответа не унифицирован» перечисляет четыре инструмента и статистики среди них нет. Реальная форма:

```json
{"items": [{"id": 150765736, "total": {"base": {"shows": 0, "cpm": "0", "ctr": 0}}}], "total": {"base": {…}}}
```

Значения `spent`/`cpm`/`cpc`/`cpa` приходят **строками**, `ctr`/`cr` — числами (доля, не проценты). `ad_plans_list` тоже отдаёт больше трёх полей по умолчанию (`event_limit`, `uniq_shows_limit`, `uniq_shows_period`, `yclients_salon_id`) — утверждение «все `*_list` бедные» верно только для `campaigns`/`ad_groups`.

**Правка:** дополнить раздел «Особенности ответов сервера» обоими фактами и привести путь `items[].total.base.cpm` прямо в строке таблицы «Фактические CPM/CTR для прогноза».

**✅ Исправлено в 0.6.6.**
