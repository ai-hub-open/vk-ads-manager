# Журнал изменений

Версии — [semver](https://semver.org/lang/ru/): до 1.0 состав шагов и материалов может меняться.

## 0.6.8 — 2026-09-15

Починен путь B (наш REST): верные эндпоинты контента, объявления вложенным массивом, креативы по публичной ссылке.

- **🔴 `POST /banners.json` не существует — метод удалён из рабочего пути.** Сверено с исходником хостового сервера `ai-hub-open/vk-ads-mcp` (`src/tools/banners.ts`), который проверялся против ads.vk.com: эндпоинт отвечает `405 unsupported_http_method` с `supported_methods: ["GET"]`. `create_campaign_tree` больше не создаёт объявления отдельными вызовами — кладёт их **вложенным массивом `banners` внутрь payload группы**, одним `POST /campaigns.json` на группу; id объявлений берутся из ответа. `BannersAPI.create` оставлен заглушкой: бросает ошибку с объяснением и указанием, как правильно, вместо похода в сеть за 405. Снято противоречие между `references/vk-ads-api.md` (документировал несуществующий метод) и `references/vk-ads-mcp-integration.md`.
- **🔴 Неверный эндпоинт загрузки медиа.** `MediaAPI` постил в `/content/upload.json` — такого пути в API нет, тип контента задаётся путём: `/content/static.json` для картинок, `/content/video.json` для видео. То есть залив медиа по пути B не работал вообще, а без медиа не собирается ни одно объявление.
- **Креатив по публичной ссылке больше не пропускается.** Раньше `upload_media` искал только локальный файл `assets/images/<name>.png`; креатив, отданный маркетологом ссылкой (штатный сценарий Шага 10), молча уходил в «файл не найден — skip», группа оставалась без объявлений и залив падал целиком. Теперь источник ищется по приоритету: `image_url` / `image_urls` / `video_url` из `creatives.json` → локальный файл. Ссылка приоритетнее файла: картинка маркетолога заменяет нашу генерацию с тем же именем.
- **Перенята логика источника из `yandex-direct-manager`.** VK, в отличие от Директа, по ссылке сам не ходит — эндпоинт принимает только multipart. Поэтому ссылку скачивает клиент и отправляет байты; `text/*` в ответе распознаётся как «по ссылке страница, а не файл» (типовой случай — шаренная ссылка Google Drive) и отделяется от отказа VK по контенту. Для пути B KeepImage не нужен: мост «локальный файл → публичная ссылка» существует потому, что **хостовый MCP** не читает диск, а наш скрипт читает. Путь A через KeepImage не менялся.
- Тестов: 153. Новые проверки — эндпоинты контента, распознавание URL (включая `C:\...`, который не схема), скачивание ссылки и отправка байтов, страница вместо картинки, приоритет ссылки над файлом, карусель из списка ссылок, вложенность баннеров в payload группы и отказ `banners.create` без похода в сеть. Мутации (возврат `/content/upload.json`, отказ от вложенности) ловятся.

Требования к среде исполнения названы явно. Раньше скилл был написан под одну конкретную среду и прямо называл её инструменты: «Все скрипты запускай сам через `mcp__workspace__bash`». В другой среде агент читал инструкцию, которую не мог выполнить, и решал на ходу.

- **Новый раздел «Что нужно от среды»** в начале `SKILL.md` вместо «Главный режим: Cowork-first»: обязательный минимум — чтение и запись файлов плюс диалог; шесть остальных способностей необязательны, у каждой в таблице указано, где она нужна и что делать без неё. Правила «пользователь не оператор» сохранены, но теперь действуют при условии, что нужные способности есть.
- **Убраны названия инструментов конкретного приложения из инструкций.** Три упоминания `mcp__workspace__bash` заменены на способность «запуск кода» с приложением в скобках. Проверка MCP больше не описана как интроспекция «есть ли у меня tools `mcp__vk-ads__*`» — теперь это проверка способности с оговоркой, что имена в разных средах выглядят иначе, а искать надо по короткому имени инструмента. `WebSearch`, `WebFetch`, `computer://`-ссылки и упоминания Cowork приведены к тому же виду в `SKILL.md` и в `references/credentials.md`, `competitor-research.md`, `vk-ads-api.md`, `video-generation.md`, `pdf-generation.md`.
- **Ветки «если нет» дописаны там, где их не было.** Раньше без веток оставались Шаги 3, 4, 7 (поиск конкурентов и их рекламы — без поиска в интернете эти шаги пустые) и модули M1, M2, M3: генераторы картинок, видео и PDF требуют и запуска кода, и ключа, и сети. Теперь M1 и M2 отдают ТЗ дизайнеру и на съёмку вместо файлов, M3 — markdown-контент без сборки PDF, а Шаг 7 при отсутствии скриншотов честно остаётся невыполненным вместо выдуманных креативов.
- **Выбор пути залива на Шаге 11 привязан к способностям среды**, а не к режиму приложения: путь A требует MCP, путь B — запуска кода и токена, путь C работает на обязательном минимуме. Оговорено, что ручной `LAUNCH_GUIDE.md` агент при необходимости пишет сам, без генератора.
- **Пометка о пропуске в артефактах.** Шаг, выполненный без необязательной способности, пишет в свой артефакт строку «пропущено: нет … — сделано вместо … Потеряно: … Как добрать: …». Сводный список — обязательный раздел «Пропущено из-за среды» в `launch_log.md` и в сводном отчёте Шага 12.
