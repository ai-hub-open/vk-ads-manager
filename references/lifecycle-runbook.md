# VK Ads — Lifecycle Runbook (13 сценариев)

13 готовых сценариев для повседневной работы с активной кампанией. Каждый — план + проверки + логирование.
Приоритет путей: **MCP-инструменты `vk_ads_*`** → наш REST `scripts/vk_ads_api.py` → UI ads.vk.ru.
Каждый сценарий ниже даёт MCP-вызовы; REST-эквиваленты — в `references/vk-ads-api.md`.

## Иерархия — читать до всех сценариев

`ad_plan` (UI «Кампания») → `campaign` = `ad_group` (UI «Группа объявлений») → `banner` (UI «Объявление»).

**Таргетинг, бюджет, цель и пакет живут на `campaign` (Группе), а не на `ad_plan`.**
`ad_plan` — контейнер: имя, даты, общие лимиты показов. Правишь аудиторию или бюджет — правишь `campaign`.

## Главные правила

1. **Никогда не активировать** (`status: active`) автоматически. Только по явному «запускай» от пользователя.
2. **Никогда не удалять** сущности (ad_plans, campaigns, banners, segments, users_lists) — только `status: blocked` (пауза).
3. **Перед write — план + «ОК?»**.
4. **После операции — GET** той же сущности и подтверждение что изменения применились.
5. **Логировать в `operations_log.md`**: дата, операция, до/после, причина, кто подтвердил.

Логи нужны не для отчётности, а чтобы понимать **что и почему меняли** при анализе через неделю.

## Важные факты платформы (учитывать в сценариях)

- **Цель и объект кампании нельзя изменить после запуска** — нужна новая кампания. На просьбу «поменяй цель с трафика на лиды» не пытаться `PUT`, а объяснить и предложить новую кампанию. Источник: general/start/creating.
- **Атрибуция PostClick (по умолчанию) vs PostView** (действия после показа без клика, окно 7 дней, только события пикселя из «Целевого действия»). При чтении статистики (Сценарии 1, 8, 11) учитывать тип атрибуции — иначе конверсии читаются неверно. Источник: general/sites/site_attribution.
- **Автоудаление:** кампании без показов/кликов за 180 дней автоматически получают статус «Удалена». Источник: general/start/delete_campaign.
- **Массовое редактирование** в UI — до 50 кампаний/групп/объявлений за раз (бюджет, даты, соцдем, регионы, интересы, площадки). Полезно как fallback при большом числе групп. Источник: general/start/edit_campaign.
- **Статус ОРД.** После создания объявление проходит не только модерацию, но и ОРД: статус «Ожидание» (до 10 дней) → «Принято» (выдан ERID) / «Отклонено». Запуск считать завершённым только после присвоения ERID. Источник: ord/ord_status.

## Сценарий 1. Общий отчёт по кабинету (Read)

**Триггер:** «Как у нас VK?», «Что в VK Рекламе?», «Отчёт по кампании»

**Действия:**
1. `vk_ads_campaigns_list(fields="id,name,status,objective,budget_limit,budget_limit_day,ad_plan_id,issues", limit=100)`
   ⚠️ Без `fields` вернутся только `id`, `name`, `package_id` — ни статуса, ни бюджета.
2. Для активных: `vk_ads_statistics_day(entity="campaigns", ids="<id через запятую>", date_from=<сегодня-7>, date_to=<сегодня>)`
   ⚠️ `ids` обязателен, режима «по всему кабинету» нет.
3. Агрегировать по cost, impressions, clicks, CTR, CPC, conversions, CPL.
   ⚠️ `budget_limit`/`budget_limit_day` приходят **в копейках** (`6000000` = 60 000 ₽), `ctr` — доля, не проценты.
   Пользователю показывай пересчитанные значения.

**Вывод в чат:**

```
📊 VK Реклама — последние 7 дней

Кампания «AiSMM SMM-фрилансеры» (active)
  Бюджет за период: 18 240 ₽ из 21 000 ₽
  Конверсии: 76 (регистрации)
  CPL: 240 ₽ (план 250) ✅
  CTR: 1.2% (нормально)

Кампания «AiSMM Эксперты» (active)
  Бюджет за период: 11 100 ₽ из 14 000 ₽
  Конверсии: 28
  CPL: 396 ₽ (план 300) ⚠️
  CTR: 0.8% (низкий, креатив устарел?)

Кампания «AiSMM Тест блогеров» (blocked)
  Не открутилась — на паузе.

→ Рекомендация: разобрать креативы по кампании «Эксперты». Хочешь Сценарий 8 (оптимизация)?
```

## Сценарий 2. Изменение бюджета (Write)

**Триггер:** «Увеличь / сократи бюджет», «Подними/опусти на X тыс»

**Действия:**
1. `vk_ads_campaigns_get(campaign_id=..., fields="id,name,budget_limit,budget_limit_day")` — текущий бюджет
   ⚠️ Значения в **копейках** (`6000000` = 60 000 ₽).
2. План: «Группа X, бюджет был A → станет B. Дневной/общий. Это +/- N% от плана. ОК?»
3. После «ОК» — `vk_ads_campaigns_update(campaign_id=..., payload={"budget_limit_day": <копейки>})`
4. `vk_ads_campaigns_get(campaign_id=...)` — проверка
5. Лог: дата, ID, "budget: A → B, причина: <X>", подтверждение

**Безопасность:**
- Никогда не двигай бюджет более чем на 50% за один шаг (алгоритм надо переучивать)
- Не уменьшай ниже 300 ₽/день (минимум VK; для Дзена — 10 000 ₽). Источник: general/start/budget_limits

## Сценарий 3. Пауза / запуск кампании (Write)

**Триггер:** «Пауза», «Поставь на паузу», «Запусти снова»

**Действия:**
1. `vk_ads_campaigns_get(campaign_id=..., fields="id,name,status,ad_plan_id,issues")` — текущий статус.
2. Пауза/запуск **группы**: `vk_ads_campaigns_set_status(campaign_id=..., status="blocked"|"active")`.
3. Пауза/запуск **всей Кампании**: `vk_ads_ad_plans_update(ad_plan_id=..., payload={"status": "blocked"|"active"})`
   — ⚠️ у `ad_plan` метода `set_status` нет, только `update`.
4. Группа стоит, хотя статус `active` → смотри `issues`: `AD_PLAN_STOPPED` (остановлен родитель),
   `NO_MONEY` (нет средств), `NO_BANNERS_WITH_ACTIVE_STATUS` (нет живых объявлений).
5. Лог

**Для возобновления:**
**КРИТИЧНО:** возобновление = активация. Делать только по явному «запускай», а не «верни». Сначала прогнать Сценарий 10 (предзапусковый чек-лист).

## Сценарий 4. Добавить lookalike (Write)

**Триггер:** «Добавь lookalike», «Сделай похожих», «LAL от конверсий»

**Действия:**
1. `vk_ads_remarketing_segments_list` — что уже есть.
2. Источник похожести — сегмент на базе пикселя или загруженного списка.
3. Проверить минимум 1000 совпавших юзеров в источнике.
4. План: «Создаю сегмент от <источник>. Размер примерно Y. Размещу в группу Z?»
5. После «ОК» — `vk_ads_remarketing_segments_create(payload={"name": ..., "pass_condition": 1,
   "relations": [{"object_type": "remarketing_users_list"|"remarketing_counter", "params": {...}}]})`
6. `vk_ads_remarketing_segments_list` — проверка.
7. Лог

⚠️ Lookalike как отдельная сущность в API/MCP недоступен. Строится через сегменты, пиксели
и списки пользователей; если нужен именно LAL-процент — это UI ads.vk.ru. Скажи об этом прямо.

**Совет:** делать LAL каскадом — 1%, 2-3%, 4-5%. Не сразу на 5%.

## Сценарий 5. Загрузить CRM-базу (Write)

**Триггер:** «Загрузи базу клиентов», «Обнови CRM-аудиторию», «У меня список телефонов»

**Действия:**
1. Уточнить: формат базы (phone/email/vk_id), количество строк, как давно собрана
2. Для загрузки списка нужно ≥100 записей; для построения look-alike из него — ≥1000 совпавших. Если база мала — матчинг даст ещё меньше, предупредить
3. `vk_ads_users_lists_list` — что уже загружено.
4. План: «Создам список X из N контактов. После матчинга останется ~50-70%. ОК?»
5. После «ОК» — `vk_ads_users_lists_create(payload={"name": ..., "type": "email"|"phone"|"idfa"|"gaid"})`
6. `vk_ads_users_lists_upload_items(users_list_id=..., items=[<хэши>])`
   ⚠️ Загружаются **хэшированные** идентификаторы, не сырые email/телефоны.
7. `vk_ads_users_lists_list` — проверка размера совпадений.
8. Если совпало < 1000 — предупредить юзера, не создавать LAL
9. Если ≥ 1000 — спросить «делаем LAL 1% от этой базы?» (Сценарий 4)
10. Лог

**Безопасность:**
- Базы со старыми контактами (> 2 лет) — низкий матчинг
- Все базы должны быть с согласием на обработку ПДн (это не наша ответственность как агента, но напомнить)

## Сценарий 6. Изменить креатив (текст или визуал) (Write)

**Триггер:** «Измени текст», «Поправь заголовок», «Замени визуал»

**Действия:**
1. `vk_ads_banners_get(banner_id=...)` — текущая версия
2. План: «Креатив X. Было: <текст>. Станет: <текст>. ОК?»
3. После «ОК»:
   - Если простая правка текста — `vk_ads_banners_update(banner_id=..., payload={"title": ..., "description": ...})`
   - Если замена визуала — `vk_ads_content_upload_image(source_path_or_url=...)` → получить `id` → `vk_ads_banners_update` с новым `images`
4. **Важно:** после изменения креатив снова попадёт на модерацию (обычно 1-4 часа). Поясни это.
5. `vk_ads_banners_get(banner_id=...)` — проверка
6. Лог

**Если объявление отклонено модерацией.** Повторная подача — пакетный
`vk_ads_banners_remoderate(banner_ids=[...])`. Отправить можно не любое: сначала
`vk_ads_banners_list(fields="id,user_can_request_remoderation")` и бери только те, где `true`.
В ответе поле `remoderated` показывает, принята ли заявка по каждому. Отправлять без пред-чека —
холостой вызов.

**Совет:** не правь работающий креатив (с высоким CTR > 1%) — лучше создай новый и тестируй параллельно. Изменение убивает накопленный «социальный сигнал» (лайки, репосты).

## Сценарий 7. Добавить интересы / сузить аудиторию (Write)

**Триггер:** «Добавь интересы», «Сузь по соцдему», «Уточни таргет»

**Действия:**
1. `vk_ads_campaigns_get(campaign_id=..., fields="id,name,targetings,status")` — текущий таргетинг **группы**.
2. Уточнить что добавить/убрать. Новые города — сначала `vk_ads_regions_search`, `targetings.geo.regions`
   принимает числовые id.
3. План: «Группа X. Текущая аудитория: … Добавляю Z, исключаю W. ОК?»
4. Проверить что новый размер > 50K (если меньше — алгоритм не сможет оптимизировать)
5. После «ОК» — `vk_ads_campaigns_update(campaign_id=..., payload={"targetings": {...}})`
6. `vk_ads_campaigns_get(campaign_id=...)` — проверка.
7. Лог

**Совет:** изменение таргетинга в работающей группе **перезапускает обучение алгоритма** (3-5 дней). Не делать чаще раза в неделю.

## Сценарий 8. Оптимизация через неделю (Write)

**Триггер:** «Прошла неделя», «Оптимизация по VK»

**Действия:**
1. Полный read: `vk_ads_ad_plans_list` → `vk_ads_campaigns_list(fields=...)` → `vk_ads_banners_list(campaign_id=...)` →
   `vk_ads_statistics_day(entity="campaigns", ids=...)`
2. Анализ по каждой группе:
   - CTR < 0.3% + > 5000 показов → выключить креативы / поменять
   - CTR > 1.5% + > 50 кликов → масштабировать (+50% бюджета)
   - Высокий CTR + низкий CR на сайте → проблема в лендинге, не в группе
   - CPL > плана x1.5 + > 20 кликов → либо аудитория плохая, либо лендинг, либо неправильное событие
3. По каждой проблемной группе — гипотеза + предложение действия
4. Сводка в `11_optimization.md` с action plan
5. Запросить подтверждение по каждому пункту → выполнить (Сценарии 2/3/4/6/7)
6. Лог

**Не делать автоматически:**
- Не удалять группы
- Не активировать новые
- Не двигать бюджет более чем на 50%

## Сценарий 9. Переключить стратегию ставок (Write)

**Триггер:** «Переключи стратегию», «Перейди на предельную цену»

**Действия:**
1. Текущая стратегия: `vk_ads_campaigns_get(campaign_id=..., fields="id,name,budget_limit,budget_limit_day,package_id")`
   ⚠️ Модель оплаты зашита в `package_id` (`priced_event_type`), сменить её на лету нельзя —
   нужна новая группа с другим пакетом.
2. Проверка готовности к «предельной цене»:
   - Накоплено > 50 событий целевого действия
   - CPL стабильный последние 5+ дней
   - Бизнес знает свой потолок CPL
3. План: «Группа X. Стратегия: minimal_price → max_price с лимитом N ₽. ОК?»
4. **Предупредить:** при переключении объём конверсий **может временно упасть на 30-50%** — алгоритм переучивается.
5. После «ОК» — `vk_ads_campaigns_update(campaign_id=..., payload={...})`
6. Не трогать неделю, потом анализ
7. Лог

**Если предельная цена не работает (открутка стала < 30% от бюджета):**
- Поднять лимит CPL на 20%
- Если не помогло — вернуть на минимальную цену

## Сценарий 10. Предзапусковый чек-лист (Write — активация)

**Триггер:** «Активируй кампанию», «Запускай»

**Чек-лист (отметить вслух перед `status: active`):**
- [ ] Все группы внутри проверены (бюджет, таргетинг, плейсменты)
- [ ] Все креативы прошли модерацию (статус `accepted`)
- [ ] Пиксель установлен и стреляет (если цель — конверсии)
- [ ] События в пикселе замаплены на цели в кабинете
- [ ] Лендинг доступен с мобайла, форма работает
- [ ] ОРД-данные заполнены, маркировка включена
- [ ] UTM-метки на месте
- [ ] Бюджет соответствует плану
- [ ] Есть план на первые 3 дня мониторинга

После прохождения всех пунктов:
1. `vk_ads_campaigns_set_status(campaign_id=..., status="active")` — для группы;
   или `vk_ads_ad_plans_update(ad_plan_id=..., payload={"status": "active"})` — для всей Кампании
2. `vk_ads_campaigns_get(campaign_id=...)` — подтверждение
3. Поставить таймер: через 24 часа проверить (Сценарий 11)
4. Лог

## Сценарий 11. Daily check (Read)

**Триггер:** «Daily check», «Сводка за вчера», «Как вчера открутилось»

**Действия:**
1. `vk_ads_statistics_day(entity="campaigns", ids=..., date_from=<вчера>, date_to=<вчера>)`
2. Сравнить с планом и с предыдущим днём

**Вывод (5-10 строк в чате):**

```
📅 VK Реклама — вчера (15.05.2026)

— Открутилось: 4 850 ₽ (план 5 000) ✅
— Конверсий: 22 (план 20) ✅
— CPL: 220 ₽ (план 250) ✅

🟢 Кампания «SMM-фрилансеры»: CPL 195 ₽ (отлично)
🟡 Кампания «Эксперты»: CPL 290 ₽ (норма)
🔴 Кампания «Блогеры»: CPL 670 ₽ (плохо — креатив устарел?)

→ Хочешь разобрать «Блогеры»?
```

Не вываливать всю статистику. Только аномалии и общую картину.

## Сценарий 12. Корректировки по соцдему (Write)

**Триггер:** «Поправь по полу/возрасту», «Корректировки», «Сузь возраст»

В VK Реклама нет «корректировок ставок» как в Директе. Вместо этого — изменение таргетинга самой группы (Сценарий 7) или дублирование группы с разделением по соцдему.

**Действия для разделения:**
1. План: «Сейчас группа на 25-45 ж/м. Хочу разделить на 25-35 ж и 35-45 ж? ОК?»
2. После «ОК»:
   - Новая **группа** с изменённым таргетингом: `vk_ads_campaigns_create(payload={"name": ...,
     "package_id": <тот же>, "ad_plan_id": <тот же>, "targetings": {...}, "status": "blocked",
     "banners": [ <копии креативов> ]})`
   - ⚠️ Объявления передаются **внутри** payload группы. Отдельного создания баннера нет,
     «долить» в созданную группу невозможно — группа без `banners` навсегда останется пустой
     (`issues: NO_BANNERS_WITH_ACTIVE_STATUS`) и её придётся удалять и пересоздавать.
   - ⚠️ `package_id` и `ad_plan_id` обязательны. Группа без `ad_plan_id` — «сирота», невидима в UI.
3. Старую группу не удалять — `vk_ads_campaigns_set_status(campaign_id=..., status="blocked")`.
4. Лог

## Сценарий 13. Скопировать кампанию (Write)

**Триггер:** «Скопируй кампанию», «Сделай дубль»

**Действия:**
1. Read: `vk_ads_ad_plans_get(ad_plan_id=...)` + `vk_ads_campaigns_list(fields="...,targetings,package_id,ad_plan_id")`
   + для каждой группы `vk_ads_banners_list(campaign_id=...)`.
2. План: «Копирую Кампанию X со всеми группами и креативами. Поменяю: <что>. Всё в `blocked`. ОК?»
3. После «ОК» — **один атомарный вызов**:
   `vk_ads_ad_plans_create(payload={"name": ..., "status": "blocked",
     "campaigns": [{..., "package_id": ..., "targetings": {...}, "banners": [{...}]}]})`
   Пошаговая альтернатива, если payload слишком большой: `vk_ads_ad_plans_create` →
   `vk_ads_campaigns_create(payload={"ad_plan_id": <новый>, ..., "banners": [...]})` по одной группе.
4. **Проверить непустой `banners`** у каждой новой группы. Пусто → залив провалился, не отдавать как успех.
5. Не активировать. Лог.

**Совет:** перед копированием спросить какие изменения нужны (другая география / другие тексты / другой бюджет). Иначе получишь точную копию.

## Что MCP/API VK НЕ умеет — фолбеки

| Не умеет | Фолбек |
|---|---|
| Создать объявление отдельным вызовом | Только вложенным массивом `banners` внутри группы |
| Долить объявления в существующую группу | Пересоздать группу целиком |
| Lookalike как отдельная сущность | Сегменты + пиксели + списки пользователей; проценты LAL — UI |
| Сменить `set_status` у `ad_plan` | `vk_ads_ad_plans_update({"status": ...})` |
| Разрезы статистики (age / region / placement) | UI ads.vk.ru |
| Асинхронные отчёты | Их нет; `statistics_summary` / `statistics_day` с явным `ids` |
| Список ранее загруженного контента | Сохраняй `id` из ответов загрузки |
| Справочники `interests`, `sectors`, `browsers`, `languages`, `os` | Отвечают 404 — не строй на них таргетинг |
| Локальные файлы в `content_upload_*` на хостовом сервере | Публичный http(s)-URL или путь B |
| Проверить, что пиксель стреляет | Браузер / UI |
| Авто-правила (если CPL > X — выключить) | Внешний скрипт на cron + API |
| Загрузка видео > 500 МБ | UI или предварительная компрессия |
| Тонкая настройка плейсментов (отдельные приложения) | UI |
| Загрузка кастомных шрифтов в креатив | Не поддерживается |
| Импорт креативов из других кабинетов | UI вручную |

Когда упираешься — **скажи прямо** что через API не сделать, и дай пошаговый сценарий для UI.
