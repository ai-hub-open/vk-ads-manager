# VK Реклама — Продвижение мобильных приложений

> Источники: general/apps/add_app, general/apps/app_campaign, general/apps/app_deeplinks, general/apps/apps, general/apps/integration_tracker (+ трекер-специфичные подстраницы), general/apps/rustore_*, general/apps/huawei_integration_tracker, general/agency/agency_clients. Форматы/лимиты объявлений — см. vk-ads-specs.md, здесь только ключевые цифры для приложений.

## Preflight: без этого кампанию не создать

Прежде чем заводить кампанию с объектом «Мобильное приложение», нужно пройти три шага — все, кроме создания самой кампании, делаются **[UI]** в кабинете, MCP/API их не покрывает:

1. **[UI] Добавить приложение в кабинет.** Раздел «Мобильные приложения» → «Добавить приложение» → ссылка на приложение в сторе. Источник: general/apps/add_app.
2. **[UI] Подтвердить владение приложением.** При первом подключении система выдаёт код (App ID). Этот код вставляется **в трекер** (в постбек на установку) — он используется один раз, только на этапе первого подключения, в других случаях не нужен. Доступ подтверждается автоматически, как только трекер пришлёт в VK Рекламу хотя бы одну установку или событие с этим кодом. До этого статус приложения — «Проверяем доступ».
3. **[UI] Настроить интеграцию с трекером** и присвоить событиям категории (см. ниже) — без категорий не будет статистики по событиям.

**В кампанию можно добавить только приложение со статусом** «Владелец», «Есть доступ» или «Проверяем доступ» (general/apps/add_app#status). Статусы «Запрошен доступ» и «Отклонено» для запуска кампании непригодны.

Если у приложения уже есть владелец (было подключено раньше в myTarget/VK Рекламе), нужно запросить доступ через «Добавить приложение» → «Отправить запрос»; владелец подтверждает запрос на вкладке «Права доступа» карточки приложения.

### Статусы приложения (general/apps/add_app#status)

| Статус | Что значит | Можно использовать в кампании? |
|---|---|---|
| Проверяем доступ | Ещё не пришло ни одной установки/события с кодом подтверждения, либо код не вставлен в трекер, либо вставлен, но передача событий не включена | Да |
| Владелец | Аккаунт назначен владельцем (master) — первый постбек с кодом получен | Да |
| Есть доступ | Владелец выдал доступ по запросу | Да |
| Запрошен доступ | Запрос отправлен, ответа владельца ещё нет | Нет |
| Отклонено | Владелец отказал в доступе | Нет |

Если включена передача только атрибутированных событий, а установок, полученных именно через VK Рекламу, ещё не было — статус «Проверяем доступ» может держаться долго. Чтобы ускорить подтверждение, включите передачу **неатрибутированных** событий (см. раздел про трекер ниже).

### RuStore — сокращённый путь

Для RuStore предусмотрены упрощения (general/apps/rustore_direct_installation, general/apps/rustore_direct_links):

- Если VK ID кабинета VK Рекламы совпадает с VK ID аккаунта разработчика в RuStore, статус «Владелец» присваивается **автоматически**, без постбека трекера.
- Кампанию на приложение из RuStore можно запустить **по прямой ссылке на стор, вообще без трекера** — для оптимизации на установки. Статистика по установкам в этом случае доступна только в кабинете VK Рекламы (трекер, если подключён, но не используется в кампании, отнесёт эти установки к органике).
- Для оптимизации на события внутри приложения трекер всё равно нужен.
- Доступна «бесшовная установка»: если у пользователя уже стоит RuStore, приложение ставится по клику на баннер без перехода в стор (попап внутри приложения-площадки). Условие — трекинговая (не прямая) ссылка + целевое действие «Установка».
- Дополнительные места размещения только для RuStore: раздел «Интересное», поисковая выдача RuStore (только для цели «Установка»), разделы «Игры»/«Приложения».

### AppGallery — сокращённый путь

Для приложений из Huawei AppGallery (general/apps/huawei_integration_tracker): добавление приложения и трекинг-ссылка настраиваются так же, как для Google Play/App Store, но целевая ссылка — ссылка на AppGallery (с обязательным удалением символа «#» из неё). При настройке группы объявлений для таких приложений **по умолчанию включён и не отключается таргетинг на устройства Huawei** — это гарантирует, что AppGallery физически есть на устройстве.

## Интеграция с трекером / MMP

VK Реклама поддерживает 7 трекеров (general/apps/integration_tracker), два — бесплатные:

- **MyTracker** (проект VK, бесплатный)
- **AppMetrica** (бесплатный)
- **AppsFlyer**
- **Adjust**
- **Branch**
- **Tenjin**
- **Singular**

Трекер — источник трекинговой ссылки для объявления и канал передачи статистики (установки, in-app события, доход) обратно в VK Рекламу; без него нет ни оптимизации на события, ни статистики по ним.

**Обязательная настройка для качества оптимизации** (general/apps/integration_tracker, general/apps/apps): включить передачу **неатрибутированных установок/событий**, а не только атрибутированных VK Рекламе, и включить передачу **revenue**. Больше данных на входе — точнее обучение алгоритма. У AppsFlyer это переключатель «All media sources, including organic» + «Send revenue → Values and revenue»; у AppMetrica — снятие чекбокса «Отправлять постбек только для первого целевого события»; у MyTracker — «Отправлять постбек по действиям всех пользователей» на дублирующих постбеках.

Важный нюанс с **AppMetrica**: автосозданный постбек на «Установку» нельзя редактировать и в него нельзя вписать код подтверждения владения (mt_app_id). Нужно создать **второй, отдельный постбек** на «Установку» с параметром mt_app_id, дождаться подтверждения владения — и затем этот дублирующий постбек удалить.

Часть трекеров (AppsFlyer, Adjust) поддерживает передачу **расходов по кампании (cost/spend) обратно в трекер** — включается парой переключателей и в трекере, и в кабинете VK Рекламы (general/apps/integration_tracker_appsflyer, general/apps/integration_tracker_adjust); у Adjust доступно только для кабинетов клиентов агентств. У AppsFlyer передача трат начинается только с текущего момента и захватывает предыдущие 7 дней — данные за более старый период передать нельзя.

Специфика отдельных трекеров:

- **AppsFlyer** — с 14 июля 2024 действует обязательное одобрение агентских аккаунтов (параметр `af_prt`): без предварительного согласования агентство в VK Рекламе трафик от такого агентского аккаунта не будет регистрироваться и измеряться; добавление агентства в список авторизованных — через менеджера VK Рекламы. Поддержаны Aggregated Advanced Privacy (AAP) постбеки для iOS 14.5+ — их нужно явно включить в трекере, иначе атрибуцированные установки не попадут в статистику кабинета.
- **Branch** — интеграция требует явного подключения партнёра «MyTarget» в разделе Partner Management, после чего базовые постбеки (установка) появляются автоматически.
- **Tenjin** — код App ID подставляется в отдельный коллбек «VK», кампания создаётся отдельно во вкладке Configure → Campaigns с указанием Marketing Account «VK ADS».
- **Singular** — партнёр добавляется как «VKADS» в Partner Configuration, ключевые поля — Postback Key и совпадение Event Name с названием действия в кабинете VK Рекламы.

Для всех трекеров действует общее правило: **отдельные ссылки для postview-атрибуции заводить не нужно** — postview поддержан на уровне интеграции трекера и VK Рекламы автоматически, используется обычная (postclick) трекинговая ссылка.

## [MCP] Создание кампании «Мобильное приложение»

После прохождения preflight кампания создаётся стандартным путём через API/MCP (general/apps/app_campaign), но с несколькими развилками, специфичными для приложений:

1. **Объект рекламы** — «Мобильное приложение». Доступны сторы: Google Play, App Store, RuStore, AppGallery.
2. **Тип кампании**:
   - «Привлечение новых пользователей» — охват аудитории, которая ещё не пользуется приложением.
   - «Вовлечение существующих пользователей» — реактивация тех, у кого приложение уже установлено (используется с обычными диплинками и ретаргетингом).
3. **Целевое действие**:
   - «Установка приложения» — не требует дополнительной настройки, годится как старт по умолчанию.
   - «Целевые действия» (одна из 6 категорий событий, доступных для оптимизации, см. ниже) — требует настроенной интеграции с трекером и присвоенных категорий, иначе система не увидит событие.
4. Бюджет — общий на кампанию (не на группу), задаётся в день или на весь период. Стратегия ставок применяется ко всем группам объявлений внутри кампании.
5. На уровне группы объявлений: для приложений в RuStore по умолчанию включён таргетинг на пользователей с установленным RuStore; для приложений в AppGallery — неотключаемый таргетинг на устройства Huawei.

После публикации объявление уходит на модерацию; алгоритм оптимизации начинает пересчитывать эффективность каждый день на основе достигнутых целевых событий.

### Оценка результата

Ключевые метрики продвижения приложений (general/apps/app_campaign): количество установок, стоимость установки, количество целевых событий внутри приложения, время до события. Смотрятся в дашборде и расширенной статистике кабинета.

## [MCP] Диплинки в объявлениях приложения

Диплинк — ссылка, ведущая не на стартовый экран приложения, а в конкретный раздел (карточка товара, акция, запись). Задаётся в объявлении на этапе создания креатива через API/MCP. **Universal Links в VK Рекламе не поддерживаются** (general/apps/app_deeplinks).

### Обычные диплинки (Regular deep link)

Подходят для аудитории, у которой приложение уже установлено (в т.ч. ретаргетинг). Если приложения нет — пользователь уходит в стор, а диплинк срабатывает уже после установки, открывая стартовый экран (не целевой раздел). Синтаксис параметра диплинка зависит от трекера:

| Трекер | Параметр | Пример |
|---|---|---|
| MyTracker | `mt_deeplink` | `...&mt_deeplink=domain://path/to/product` |
| AppsFlyer | `af_dp` | `...&af_dp=domain://path/to/product` |
| AppMetrica | `appmetrica_deep_link` (в параметре `referrer` целевой ссылки на Android; на iOS — тот же параметр в целевой ссылке) | `...&referrer=appmetrica_deep_link=domain://path/to/product` |
| Adjust | `deep_link` (рекомендуется url-encoded) | `...&deep_link=domain://path/to/product` |

Для Android как альтернатива поддержана технология intent (у всех перечисленных трекеров). Корректность диплинка можно проверить в кабинете кнопкой «Проверить с помощью QR-кода».

### Отложенные диплинки (Deferred deep link)

Подходят для новых пользователей без установленного приложения: система запоминает целевой раздел и открывает его сразу после установки и первого запуска. Формируются **строго по инструкции конкретного трекера** (единого параметра, как у Regular, нет). Ключевое ограничение: **отложенные диплинки не работают в SKAD-кампаниях** (реклама iOS-приложений через SKAdNetwork).

### SKAdNetwork (iOS 14.5+) — на что это влияет

Начиная с iOS 14.5 конверсии на iOS отслеживаются через SKAdNetwork, а не через IDFA (general/apps/skadnetwork). Ограничения, которые нужно учитывать при подготовке такой кампании: рекламировать iOS-приложение через SKAdNetwork может только владелец приложения или тот, кому владелец выдал доступ; нужна трекинговая ссылка именно на App Store; на приложение — не более **100 групп объявлений**; статистика по установкам обновляется с задержкой **24–48 часов**; при архивации группы объявлений слот Apple ID освобождается только через 7 дней. Отложенные диплинки в таких кампаниях не работают (см. выше).

## Категории событий приложения

В карточке приложения (general/apps/apps) каждому in-app событию, которое трекер передаёт в кабинет, нужно присвоить категорию — это делается **[UI]**, до этого шага статистика по событиям не собирается вообще. Всего категорий 23:

Добавление в корзину, Покупка, Авторизация, Регистрация, Оформление подписки, Достижение уровня, Начало оформления заказа, Добавление платёжной информации, Контакт, Получение потенциального клиента, Просмотр контента, Использование поиска, Добавление в список желаний, Запись на приём, Использование пробной версии, Подача заявки, Прохождение обучения, Оценка, Получение награды, Трата внутренней валюты, Просмотр рекламы, Покупка товара, Время проведённое в игре, Открытие приложения.

Из них **только 6 доступны как цель оптимизации** при создании кампании: Покупка, Добавление в корзину, Авторизация, Регистрация, Оформление подписки, Достижение уровня. Остальные 17 категорий работают только на статистику и на построение аудиторий ретаргетинга (используются потом в новых кампаниях) — оптимизировать рекламу напрямую на них нельзя.

## Форматы объявлений приложения

Детальные лимиты по всем перформанс-форматам сверены в vk-ads-specs.md — здесь только специфика приложений (source: general/apps/app_campaign):

- **Универсальное объявление** — формат по умолчанию, система сама подбирает вариант под площадку. Заголовок до 40 знаков, короткое описание до 90, длинное (для лент VK/OK) до 220, текст у кнопки до 30, описание для карусели товаров до 50 (не более 3 «!»).
- **Карусель слайдов** — от 3 до **6 слайдов**, заголовок слайда до **25 знаков**, описание слайда до **32 знаков**, трекинговая ссылка вводится отдельно для каждого слайда (даже если ссылки одинаковые).
- **Галерея медиафайлов** — коллаж или слайдер, **без текста и кнопки**, от **2 до 10** медиафайлов (фото/видео вперемешку).

Все форматы — надстройки над обязательными полями шага «Объявление» (логотип, трекинговая ссылка, диплинк, CTA из списка, медиафайлы); карусель и галерея добавляются кнопкой «Добавить ещё формат».

## Права доступа: владелец, приглашённый, агентство

- **Владелец (статус «Владелец», master)** — первый, кто подключил приложение и получил постбек с кодом подтверждения. Может: размещать рекламу приложения; настраивать категории событий и смотреть статистику по ним; применять оптимизацию на установки/события; выдавать доступ другим кабинетам (вкладка «Доступ» в карточке приложения).
- **Приглашённый пользователь (статус «Есть доступ»)** — получил доступ от владельца по запросу. Может размещать рекламу приложения, но оптимизацию на события и таргетинг по событиям — только если владелец явно выдал эти права. Полного управления приложением у приглашённого нет.
- **Агентский кабинет VK Рекламы не может быть владельцем мобильного приложения** — при этом **кабинет Клиента агентства может** быть владельцем (general/apps/add_app; подробнее об устройстве клиентов агентства — general/agency/agency_clients). На практике это значит: если работаете из агентского кабинета, приложение и трекер нужно подключать и подтверждать владение именно в кабинете Клиента, а не в самом Агентском кабинете.

## Чек-лист «приложение готово к запуску»

- [ ] Приложение добавлено в кабинет (general/apps/add_app), статус — «Владелец», «Есть доступ» или «Проверяем доступ»
- [ ] Владение подтверждено (или ожидается первый постбек) — код App ID вставлен в нужный параметр трекера
- [ ] Трекер выбран и подключён (MyTracker / AppMetrica / AppsFlyer / Adjust / Branch / Tenjin / Singular)
- [ ] Включена передача неатрибутированных установок и событий + передача revenue
- [ ] Для AppMetrica: дублирующий постбек с mt_app_id создан на этапе подтверждения и удалён после получения статуса «Владелец»
- [ ] В карточке приложения включено отслеживание нужных in-app событий и каждому присвоена категория (без этого — нет статистики)
- [ ] Если планируется оптимизация на событие — категория входит в список из 6 доступных для оптимизации
- [ ] Трекинговая ссылка получена и проверена (для RuStore/AppGallery — с учётом их специфики целевой ссылки)
- [ ] [MCP] Диплинк (обычный и/или отложенный) сформирован по синтаксису конкретного трекера и проверен через QR-код
- [ ] Если кампания на iOS через SKAD — отложенные диплинки не используются
- [ ] Для приложений RuStore/AppGallery — проверены дефолтные таргетинги (RuStore-аудитория, устройства Huawei) и, при желании бесшовной установки, используется трекинговая, а не прямая ссылка
- [ ] Права доступа выданы нужным кабинетам (если приложением управляет не один кабинет); учтено, что Агентский кабинет не может быть владельцем — владение оформлено на кабинет Клиента агентства
- [ ] Форматы объявления подготовлены с учётом лимитов (универсальное / карусель до 6 слайдов / галерея 2–10 файлов)
