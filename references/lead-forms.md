# VK Реклама — Лид-формы

> Источники: general/lead_forms/lead_forms, general/lead_forms/business_card, general/lead_forms/landing, general/lead_forms/split_test, general/lead_forms/surveys, general/lead_forms/brand_lift, general/lead_forms/lead_ads_tips.

## Главное: как это устроено через API/MCP

**[MCP]** VK Ads API умеет создать только **объявление-обёртку**, которое ссылается на `lead_form_id`. Сама форма (шаги «Оформление → Вопросы → Результат → Настройки», дизайн, вопросы, юр.данные, уведомления) публичного метода создания/редактирования не имеет.

**[UI-fallback]** Саму лид-форму нужно собрать вручную в кабинете: раздел «Лид-формы и опросы» → «Создать лид-форму». Только после этого её `id` можно передать в объект продвижения кампании через API.

Практический вывод для скилла: на этапе плана — предлагать клиенту готовую структуру формы (тип, заголовки, вопросы, поля контактов, экран результата) как ТЗ, но финальную сборку и все визуальные настройки — это шаг для человека в кабинете. Знать лимиты и логику конструктора обязательно, чтобы ТЗ было валидным с первого раза и не отклонялось модерацией/не переделывалось.

## Конструктор формы: 4 шага [UI]

Раздел «Лид-формы и опросы» → «Создать лид-форму». Все правки видно в живом предпросмотре справа (светлая/тёмная тема, десктоп/мобайл).

### Шаг 1. Оформление

Общие поля:
- Название лид-формы — только для кабинета, не видно пользователям.
- Логотип — обязательное поле.
- Название компании — обязательное поле.
- Стили — цвет формы (пресеты или пипетка; кнопка сама выбирает контрастный цвет текста, обложка — градиент под цвет; вручную эти цвета не меняются).
- Обложка — картинка-подложка первого экрана, 16:9, мин. 1080×607 px (слаг lead_forms/lead_forms).

Дальше — выбор **типа формы**, от него зависит набор полей:

| Тип | Заголовок | Описание | Особенность |
|---|---|---|---|
| **Компактная** | ≤ 50 знаков | ≤ 35 знаков | 1 слайд, сразу поля контактов |
| **Больше текста** | ≤ 50 знаков | ≤ 350 знаков | вводный слайд + на шаге 2 можно добавить вопросы |
| **Лид-магнит** | ≤ 50 знаков (заголовок опроса) | — | бонус за заявку: «Скидка» (сумма ₽ или %) либо «Бонус» (название бонуса ≤ 30 знаков, ссылка добавляется на шаге 3 «Результат») |

Слаг: general/lead_forms/lead_forms.

### Шаг 2. Вопросы

- **Контактная информация** — список полей ввода. По умолчанию имя + телефон, остальные поля добавляются кнопкой «Добавить контактные данные», порядок можно перетаскивать. Если у пользователя заполнен профиль соцсети — поля могут быть предзаполнены автоматически.
- **Вопросы** — необязательный мини-опрос внутри формы (заголовок + варианты ответа). Можно сделать обязательными для ответа — флаг ставится на шаге 4.
- Отдельная галочка «Ссылка на соцсеть» в блоке «Вопросы» — если нужно получать не только контакты, но и профиль пользователя, оставившего заявку.

Совет из lead_ads_tips: не переусложнять — чем меньше полей и вопросов, тем выше completion rate.

### Шаг 3. Результат

Экран после отправки: заголовок + описание, можно добавить сайт, телефон, промокод. Для типа «Лид-магнит» с наградой «Бонус» здесь же указывается ссылка на скачивание промо-материалов.

### Шаг 4. Настройки

- Юридическая информация о компании → на её основе автоматически формируется текст согласия на обработку персональных данных (обязательный чекбокс в форме).
- Флаг «Обязательные вопросы» — делает все вопросы формы обязательными разом.
- Настройка уведомлений о новых лидах (см. раздел ниже).

После сохранения форма попадает в список раздела «Лид-формы и опросы» и становится доступна для выбора в кампании (через UI или её `id` — через API).

## Капча, черновики, тест-отправка [UI]

- **Капча.** Все лид-формы защищены капчей; включается автоматически при подозрении на нетипичную активность — помогает отсекать мусорные заявки. Отдельно настраивать не нужно.
- **Черновики.** Незаконченную форму можно сохранить как черновик — он отображается в начале списка форм, продолжить редактирование можно в любой момент. После финального сохранения формы черновик удаляется автоматически.
- **Тест-отправка.** Наведите курсор на форму → иконка конверта → «Отправить тестовый лид». Ограничение — раз в 5 секунд. Важно: email, указанный для уведомлений, должен быть подтверждён в настройках кабинета — иначе тестовый лид не придёт.
- Редактирование — наведите на название формы → «Редактировать». Удаление — только через архивацию (список → «Действия» → «Архивировать»).

Слаг: general/lead_forms/lead_forms.

## Уведомления о лидах [UI]

Два канала, настраиваются на шаге 4:

1. **Почта** — до **10 email-адресов**. Каждый должен быть подтверждён в настройках кабинета, иначе уведомления (в т.ч. тестовые) не придут.
2. **VK Messenger** — уведомления приходят личным сообщением VK ID, привязанному к кабинету. Несколько профилей ВКонтакте добавить нельзя — только один получатель, тот, на кого зарегистрирован кабинет.

**Важно для агентств:** VK Messenger-уведомления **не работают**, если тип кабинета — «Клиент агентства». Канал доступен только для кабинетов с типом «Физлицо» (прямой рекламодатель), зарегистрированных через VK ID. Если агентство ведёт кабинет клиента и клиенту нужны уведомления в мессенджер — единственный рабочий вариант это почта (до 10 адресов) или интеграция с CRM/коллтрекингом (см. ниже).

Чек по неполучению уведомлений (из FAQ):
1. Кабинет зарегистрирован через VK ID (страницу ВКонтакте)?
2. Тип кабинета — «Физлицо», не «Клиент агентства»?
3. На шаге 4 отмечена галочка «Получать уведомления через VK Мессенджер»?
4. Проверяете ту же страницу, на которую зарегистрирован кабинет (сменить получателя технически нельзя)?
5. Для почты — просто проверить корректность email.

Слаг: general/lead_forms/lead_forms.

## Интеграции с CRM / коллтрекингом [UI]

Лид-формы VK можно синхронизировать напрямую с внешними сервисами — настройка каждой интеграции идёт **на стороне сервиса**, не в кабинете VK Рекламы (кабинет только выдаёт доступ/токен):

- VK CXHub
- Albato
- Callibri
- Calltouch
- Lead2Call
- Roistat
- Smartis
- UIS (Comagic)
- Wahelp
- Битрикс24 (через 1С)
- amoCRM

**YCLIENTS временно недоступен** (на момент справки VK) — при запросе клиента предупреждать сразу.

Куда идти: инструкция настройки — в справке самого сервиса-интегратора (у каждого своя страница про интеграцию с VK Рекламой), не в help.ads.vk.com. Для агентств это основной способ получать лиды в CRM, раз VK Messenger для типа «Клиент агентства» не работает.

Слаг: general/lead_forms/lead_forms.

## Визитка (business_card) [UI, отчасти MCP-совместимо]

**Что это.** Карточка с описанием предложения и контактом для связи — формат «реклама без сайта и без сообщества». Пользователь кликает по объявлению и сразу связывается по указанному каналу (профиль ВКонтакте, телефон, ссылка на мессенджер).

**Где показывается.** ВКонтакте, Одноклассники, проекты VK, Рекламная сеть.

**Обязательные поля при создании:**
- Название визитки (для кабинета)
- Логотип
- Название компании
- Заголовок
- Длинное описание
- Контакт (профиль / телефон / мессенджер)
- Изображения — опционально, только картинки (видео нет)

**Подтверждение телефона.** Если контакт — номер телефона, его нужно верифицировать (блок «Телефон» → «Подтвердить» → SMS-код). Один раз для номера — далее не требуется.

**Целевое действие.** Для визиток доступно только одно целевое действие — **«Клики по рекламе»** (клики по способу связи: профиль/мессенджер/сайт/телефон).

**Как создаётся.** Либо во время быстрого запуска кампании (вкладка «Быстрый запуск» → «Создать визитку» → можно сгенерировать текст/картинки автогенерацией по описанию, либо заполнить вручную), либо заранее в разделе «Лид-формы и опросы» → вкладка «Визитки».

**Особенность:** правки визитки автоматически применяются во всех кампаниях, где она уже используется — не нужно пересоздавать объявления.

Столбец «Результат» в статистике для визиток = количество переходов по кнопке связи.

Слаг: general/lead_forms/business_card.

## Лендинг-прогрев формы (landing) [UI]

Встроенный конструктор простой посадочной страницы, которая показывается **перед** лид-формой — чтобы прогреть пользователя перед тем, как просить контакты.

**Логика:** клик по объявлению → лендинг → кнопка внизу (CTA, текст кастомизируется) → лид-форма открывается только после клика по этой кнопке.

**Как включить:** при создании лид-формы, на шаге 1 «Оформление» → переключатель «Собрать лендинг» → «Редактировать» → визуальный редактор, блоки трёх типов (текст / изображение / видео), можно менять порядком (drag за левый верхний угол блока).

**Требования к медиа в лендинге:**
- Изображения: иконка 256×256 px; соотношения 1:1 / 4:5 / 16:9 / 9:16; разрешения 600×600 / 1080×1350 / 1080×607; до 5 МБ; jpg/png.
- Видео: те же соотношения; мин. ширина 600 px; длительность ≤ 180 сек; до 90 МБ; mp4/mov.

**Обязательные поля для сохранения:** название компании (≤ 30 знаков), заголовок (≤ 70 знаков), логотип, минимум один блок в редакторе.

**Ограничения:**
- Лендинг жёстко привязан к одной конкретной лид-форме.
- Ссылки в тексте лендинга **не кликабельны** (ссылку на сайт нужно указывать отдельно на шаге 3 «Результат» самой лид-формы — она появится пользователю уже после отправки формы).
- Статистика по показам/поведению на лендинге рекламодателю пока недоступна.

Слаг: general/lead_forms/landing.

## Сплит-тест лид-форм (split_test) [UI]

Тестирование нескольких вариантов формы для автоматического выбора самой конверсионной.

- До **4 лид-форм** одновременно (минимум 2).
- Все формы нужно создать заранее, затем при создании кампании с объектом «Лид-формы и опросы»: выбрать первую форму → включить переключатель «Сплит-тест» → «Выбрать ещё одну» → добавить остальные.
- Критерий победителя — **стоимость привлечения заявки** (CPL), не CTR и не открытия сами по себе.
- Порог принятия решения — **384 открытия лид-формы** (совокупно по всем вариантам; число открытий может не совпадать с числом кликов). После достижения порога система анализирует результаты и переключает показ только на форму-победителя.
- **После запуска кампании формы, участвующие в сплит-тесте, редактировать нельзя** — это ломает корректность работы алгоритма выбора.

Слаг: general/lead_forms/split_test.

## Опросы и Brand Lift — кратко (не для сбора контактов)

- **Опросы (surveys)** — количественные исследования с анонимными ответами (гипотезы о продукте, отношение к бренду). До 24 вопросов, 1-7 вариантов ответа на вопрос, поддерживают нелинейную логику и стоп-экраны. Контакты не собирают — для лидов нужна именно лид-форма, не опрос. Слаг: general/lead_forms/surveys.
- **Brand Lift** — отдельный инструмент измерения влияния охватной (баннер/видео) кампании на восприятие бренда (запоминаемость, узнаваемость, намерение купить и т.п.). Требует бюджет от 2 млн ₽ (или ~140 тыс ₽/день), охват от 500 тыс., длительность кампании и группы от 14 дней. Тоже не собирает контакты пользователей. Слаг: general/lead_forms/brand_lift.

Оба инструмента живут в том же разделе «Лид-формы и опросы», но решают другую задачу — их не нужно путать с лид-формой, когда цель клиента именно «собрать заявки».

## Чек-лист «лид-форма готова»

- [ ] Тип формы выбран осознанно: Компактная (быстрый минимум) / Больше текста (нужен вводный слайд + вопросы) / Лид-магнит (есть что дать взамен — скидка/бонус)
- [ ] Заголовок ≤ 50 знаков; описание в лимите типа (≤ 35 компактная / ≤ 350 «больше текста»)
- [ ] Логотип и название компании заполнены (обязательные поля)
- [ ] Поля контактов минимальны и оправданы (имя+телефон по умолчанию — не раздувать без необходимости)
- [ ] Юридические данные компании внесены → согласие на обработку ПДн сформировано
- [ ] Экран результата настроен (текст + при необходимости сайт/промокод/ссылка на бонус)
- [ ] Уведомления настроены: email (до 10, подтверждены) и/или VK Messenger (только если кабинет НЕ «Клиент агентства»); для агентских кабинетов — предусмотрена CRM/коллтрекинг-интеграция
- [ ] Тестовый лид отправлен и дошёл до получателя
- [ ] Если нужен прогрев — лендинг собран, обязательные поля лендинга заполнены, ссылка на сайт вынесена в шаг 3 формы (не в текст лендинга)
- [ ] Если тестируем варианты — сплит-тест настроен ДО запуска (2-4 формы), после старта формы в тесте не трогаем
- [ ] `lead_form_id` передан в объект продвижения кампании через API/MCP; форма создана и провалидирована в UI заранее — API её не создаёт
