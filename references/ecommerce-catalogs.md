# VK Реклама — E-commerce: каталоги, фиды, динамический ретаргетинг

> Материал охватывает то, что нужно для запуска и ведения товарной рекламы через API/MCP: структуру каталога, требования к фиду, события ретаргетинга, группы товаров, макросы и специфику маркетплейсов. Общие основы пикселя и типов аудиторий — см. audiences-and-lookalike.md (раздел «6. Каталог для e-commerce»), здесь не дублируются.

## Архитектура: каталог, объект рекламы, типы кампаний

**Каталог товаров** — сущность в Центре коммерции, где хранятся все позиции, которые рекламируются или продаются: товары, недвижимость, транспорт, услуги, авиарейсы, гостиницы. Источник: `general/ecomm/feed_catalog/ecomm_catalog`.

### Источники каталога (4 способа создания)
1. **Фид по ссылке** — URL на удалённое хранилище (файл фида на стороне рекламодателя), с опциональной HTTP-авторизацией (логин/пароль в форме или прямо в URL `http://user:pass@host/feed.xml`). [MCP]
2. **Товары сообщества ВКонтакте** — указывается ссылка на сообщество; каталог (и для товаров, и отдельно для услуг) создаётся автоматически, без файла фида. Требует прав администратора сообщества и входа под тем же VK ID. [UI/MCP гибрид]
3. **Маркетплейс** — Ozon, Wildberries, AliExpress Россия, Яндекс.Маркет; каталог собирается через API маркетплейса по ссылке на магазин + ключу доступа. [UI]
4. **Файл вручную** — загрузка файла фида (до 100 МБ) с выбором категории (вертикали). [MCP через product_feeds-инструменты / UI для первичной загрузки]

Источник: `general/ecomm/feed_catalog/ecomm_catalog`.

### Объект рекламы «Каталог товаров» и типы кампаний
Кампания создаётся с рекламным объектом «Каталог товаров» → далее выбирается подтип: **Сайт**, **Мобильное приложение**, **Сообщество ВКонтакте**, **Магазин на маркетплейсе**. Источник: `general/ecomm/feed_campaign`, `general/ecomm/feed_campaign_community`, `general/ecomm/feed_campaign_marketplace`.

Внутри объекта — два типа кампании:
- **Привлечение потенциальных клиентов** — для новых покупателей; рекомендуется как стартовый тип, максимально широкие аудитории (алгоритм сам находит заинтересованных).
- **Динамический ретаргетинг** — напоминание тем, кто уже взаимодействовал с товарами. Для сайтов/приложений доступны аудитории: вся аудитория сайта/приложения, вся аудитория каталога, аудитория конкретной группы товаров; условие ретаргетинга (любое действие / не купили / посмотрели, но не добавили в корзину / добавили в избранное, но не купили / добавили в корзину, но не купили / допродажи) и период 0–365 дней (по умолчанию 0–30). Источник: `general/ecomm/feed_campaign`.

**Целевые действия:** просмотры/клики — без доп. настроек; просмотр/добавление в корзину/покупка/избранное — доступны только после подключения пикселя (сайт) или трекера (приложение). Источник: `general/ecomm/feed_campaign`.

**Особенность маркетплейсов:** у VK Рекламы нет доступа к событиям внутри маркетплейса — ретаргетинг строится **только по кликам** на объявления, а не по действиям в самом маркетплейсе. Поэтому для динамического ретаргетинга маркетплейса сначала обязательно нужно прогнать кампанию «Привлечение потенциальных клиентов», чтобы накопить клики. Источник: `general/ecomm/feed_campaign_marketplace`.

## Требования к фиду

Источник: `general/ecomm/feed_catalog/ecomm_catalog_requirements`.

| Параметр | Значение |
|---|---|
| Размещение | По прямой ссылке на удалённое хранилище (без редиректов) **или** загрузкой файла в кабинете |
| Макс. размер по ссылке | **8 ГБ** |
| Макс. размер при загрузке файлом | **100 МБ** |
| Макс. число товаров в файле | **4 000 000** |
| Кодировка | UTF-8 или Windows-1251 |
| Архивы | ZIP, GNU ZIP (.gz), Bzip2 (.bz2) |
| Спецсимволы в тексте | HTML-теги запрещены; `<` → `&lt;`, `>` → `&gt;`, `&` → `&amp;`, `'` → `&apos;`, `"` → `&quot;` |

**Форматы:**
- **XML** — фиды по спецификации Yandex (YML) и Google. Есть почти для всех вертикалей (товары, недвижимость, авто, услуги, авиарейсы; гостиницы и лекарства — только по Google-спецификации).
- **CSV** — только для фидов по спецификации Google, вертикали: Товары, Недвижимость, Транспортные средства, Услуги.
- **TSV** — только для фидов по спецификации Google, вертикали: Товары, Недвижимость, Транспортные средства, Услуги, Гостиницы, Авиарейсы.

### Обязательные/опциональные поля товарного фида (спецификация Google, вертикаль «Товары»)
Источник: `general/ecomm/feed_catalog/ecomm_catalog_g_goods`.

**Обязательные:** `id` (≤128 симв., уникален, латиница/цифры/`_`/`-`), `title` (≤256, не капсом/не строчными), `price` (число + код валюты ISO 4217 через пробел, десятичная точка, значение >0, например `700.99 RUB`), `link` (домен продавца, http/https), `image_link` (JPEG/PNG/GIF/WEBP, рек. 600px, мин. 300px, макс. 6000px по большей стороне, квадрат 1:1, однотонный фон, без водяных знаков — при смене картинки обязательно менять URL), `brand`.

**Опциональные (частые):** `availability` (True/False), `description` (≤256, без HTML/капса/контактов), `condition` (new/refurbished/used), `age_group`, `gender`, `sale_price`/`min_price`/`max_price`, `product_type` (fb_product_category/google_product_category, ≤750 симв.), `custom_label_0…4` (сегментация, см. ниже), `rating` (1–5, float).

**Спецификация Yandex (YML)** использует другие имена полей: `offer.id`, `model`, `vendor`, `price`, `currencyId`, `url`, `picture`, `oldprice`, `typePrefix`, `name` (для упрощённого типа товара) — источник `general/ecomm/feed_catalog/ecomm_catalog_y_goods`.

### Вертикали (кратко, полные спеки — по ссылкам)
Помимо товаров, Центр коммерции поддерживает отдельные наборы полей для:
- **Недвижимость** — `general/ecomm/feed_catalog/ecomm_catalog_estate` (Google-подобная) и `..._y_estate` (Yandex); обязательные поля включают `location` (address/locality/region/country), `price`, `image_link`, `link`.
- **Транспортные средства** — `general/ecomm/feed_catalog/ecomm_catalog_transport`; обязательные: `brand`, `model`, `state_of_vehicle` (new/used/cpo), `year`.
- **Услуги** — `general/ecomm/feed_catalog/ecomm_catalog_service`; обязательное поле `worker_type` (physical/juridical).
- **Авиарейсы** — `general/ecomm/feed_catalog/ecomm_catalog_avia` и `..._g_avia` (Google-спека: добавлено обязательное `ID`, `Origin/Destination name` обязательны, есть опциональный `brand`); только CSV/TSV для Google-варианта.
- **Гостиницы** — `general/ecomm/feed_catalog/ecomm_catalog_hotel` и `..._g_hotel` (Google-спека, только CSV/TSV).
- **Лекарства** — `general/ecomm/feed_catalog/ecomm_catalog_g_meds`; обязательное поле `pharma_reg_number` (регистрационный номер в гос. реестре ЛС), опциональные `dosage`, `form_factor`.

Каждый товар может иметь до 5 меток `custom_label_0…custom_label_4` (≤256 симв. каждая) — используются для групп товаров.

### Обязательные поля для мобильных приложений (во всех вертикалях)
`android_tracking_url` / `ios_tracking_url` — трекинг-ссылки (домены зависят от трекера: MyTracker `trk.mail.ru`, Adjust `app.adjust.com`, AppsFlyer `app.appsflyer.com`, AppMetrica `redirect.appmetrica.yandex.com`), `android_app_link` (Android app ID), `mobile_ios_app_store_id`, `mobile_android_app_link` / `mobile_ios_app_link` (диплинки, схемы URL должны совпадать на обеих платформах). Источник: `general/ecomm/feed_deeplinks`.

**Диплинки** бывают обычные (Regular — для пользователей с уже установленным приложением, для ретаргетинга) и **отложенные** (Deferred — для новых пользователей: сервер запоминает целевой экран и открывает его после установки приложения из стора; требуют трекинг-библиотеку, например MyTracker). Важно: **трекинг-ссылки в формате Universal Links (`onelink.me` AppsFlyer, `adj.st` Adjust) не поддерживаются** в объекте «Каталог товаров». Амперсанды в GET-параметрах трекинг-ссылок нужно экранировать как `&amp;` (или обернуть ссылку в CDATA). Источник: `general/ecomm/feed_deeplinks`.

## [MCP] События динамического ретаргетинга

Без корректно переданного `product_id` товарная реклама (динамический ретаргетинг) не работает — это ключевое правило всей темы.

### Веб-события (пиксель, `_tmr.push`)
Источник: `general/ecomm/dyn_ret/ecomm_web_dynrem`.

Обязательные события — просмотр карточки товара, добавление в корзину, покупка; опционально — добавление в избранное (`add_to_wishlist`). Настраиваются во вкладке «Источники событий» → «Сайты» → пиксель → «События», категория события выбирается из выпадающего списка, условие наступления — «JS-событие».

```javascript
// Просмотр карточки товара
_tmr.push({ type: "reachGoal", id: PIXEL_ID, value: "VALUE", goal: "viewProduct", params: { product_id: "PRODUCT_ID" }});

// Добавление в избранное
_tmr.push({ type: "reachGoal", id: PIXEL_ID, value: "VALUE", goal: "addToWishlist", params: { product_id: "PRODUCT_ID" }});

// Добавление в корзину
_tmr.push({ type: "reachGoal", id: PIXEL_ID, value: "VALUE", goal: "addToCart", params: { product_id: "PRODUCT_ID" }});

// Покупка (один товар)
_tmr.push({ type: "reachGoal", id: PIXEL_ID, value: "VALUE", goal: "purchase", params: { product_id: "PRODUCT_ID" }});

// Покупка (несколько товаров)
_tmr.push({
  type: "reachGoal", id: PIXEL_ID, value: "VALUE", goal: "purchase",
  params: { product_id: ["PRODUCT_ID_1", "PRODUCT_ID_2", "PRODUCT_ID_N"] }
});
```

`PRODUCT_ID` обязан совпадать по формату с ID товара в фиде (поле `id`/`offer.id`). `VALUE` — стоимость товара; рекомендуется передавать, чтобы точнее таргетировать и оптимизировать, а также считать метрики Доход/ДРР/ROMI. Событие `addToCart` лучше вызывать в момент добавления, а не при каждом открытии корзины со всеми товарами — иначе задвоение статистики.

Для сложных витрин можно передавать данные через **Google Tag Manager** (`dataLayer`, расширенная электронная торговля GA4) — VK Реклама умеет читать `dataLayer` при активированном сборе событий в настройках пикселя.

### Мобильные события (in-app, через трекеры)
Источник: `general/ecomm/dyn_ret/ecomm_mob_dynrem`.

Обязательные in-app-события: `viewProduct`, `addToCart`, `purchase`; опционально `add_to_wishlist`. Поддерживаемые трекеры: **MyTracker, Adjust, AppsFlyer, AppMetrica, Branch**.

Порядок настройки: (1) в SDK трекера передать событие с параметром ID товара; (2) в кабинете трекера настроить постбеки/партнёра «VK Ads (ex. myTarget)»; (3) в VK Рекламе в настройках приложения выбрать категорию для каждого события (Просмотр карточки товара / Добавление в корзину / Покупка / Добавление в избранное); (4) при необходимости вручную указать название параметра ID товара.

Допустимые названия параметра с ID товара (система ищет автоматически): `af_content_id`, `productid`, `fb_content_id`, `offerId`, `content_id`, `content`, `product_id`, `product`, `offer_id`, `offerid`, `af_content_list`, `item_id`, `contentid`.

Пример для AppsFlyer (Android):
```java
Map<String, Object> eventValue = new HashMap<>();
eventValue.put("productid", "10001");
AppsFlyerLib.getInstance().trackEvent(context, "viewProduct", eventValue);
```

Настройка постбеков различается по трекеру: MyTracker — вкладки Postbacks + Events Sending; Adjust — Campaign Lab → New Partner → VK Ads (ex. myTarget) → маппинг событий и параметра ID товара; AppsFlyer — Integrated Partners → myTarget → In-App Events Postback → Add Manually; AppMetrica — новый трекер на платформу, вкладка Ecommerce, шаблоны `ViewProduct/AddToCart/Purchase Ecom Postback`; Branch — Partner Management → POSTBACK CONFIG, кастомный параметр `partner_parameters`.

## Группы товаров и макросы

### Группы товаров
Источник: `general/ecomm/ecomm_interface/ecomm_groups`.

Инструмент сегментации фида для раздельных кампаний/аудиторий (например, «взаимодействовал с группой А → показывать товары из группы Б»). **До 1000 товаров в одной группе.** Три способа создания: по фильтрам (в т.ч. по `custom_label_0…4` и по автоматически рассчитанной скидке `price` vs `sale_price`), вручную выбором из списка, списком ID товаров. Копирование группы — через «Создать похожую группу». Удаление группы, используемой в активных кампаниях, требует подтверждения «Удалить и остановить кампании».

### Макросы в объявлениях
Источник: `general/ecomm/feed_macro`.

Динамические параметры для заголовка/текста/описания карточки, подставляющие значения полей фида. Набор макросов зависит от вертикали. Для товаров:

| Макрос | Соответствие в Google-спеке | Значение |
|---|---|---|
| `{{product.model}}` | `<g:title>` | Модель/название товара |
| `{{product.price}}` | `<g:price>` | Актуальная цена |
| `{{product.old_price}}` | `<g:sale_price>` | Старая цена (место отображения на баннере определяется правилами площадки, а не полем, куда вставлен макрос) |
| `{{product.min_price}}` / `{{product.max_price}}` | — | Мин./макс. цена |
| `{{product.description}}` | `<g:description>` | Короткое описание |
| `{{product.vendor}}` | `<g:brand>` | Бренд/производитель |

Аналогичные наборы есть для транспорта (`{{product.vehicle_type}}`, `{{product.body_style}}`…), недвижимости (`{{product.area_size}}`, `{{product.num_rooms}}`…), услуг (`{{product.rating}}`, `{{product.reviews_count}}`…), авиарейсов (`{{product.origin_airport}}`…) и гостиниц (`{{product.category}}`…). Если для макроса подходит слишком мало товаров фида, система предупредит; если нет ни одного подходящего товара — макрос выбрать нельзя.

## [UI] Центр коммерции

Источник: `general/ecomm/ecomm_interface/about_ecomm`. Единая точка входа для ведения каталога: вкладки **Товары**, **Группы товаров**, **Диагностика**, **События**, **История загрузок**, **Настройки**.

### Диагностика
Источник: `general/ecomm/ecomm_interface/ecomm_diagnostics`. Два уровня критичности:
- **Ошибки** — блокируют импорт фида целиком (например, невалидный URL фида) или загрузку конкретной позиции (некорректное обязательное поле).
- **Предупреждения** — товар всё же загружается, но с неполной/неверной информацией.

Частые ошибки: невалидный URL фида (должен соответствовать RFC 3986), не удалось скачать изображение (6 попыток), невалидный заголовок CSV, **в фиде нет ни одного товара в наличии — нужно минимум 3 товара со статусом «в наличии»**, некорректный формат ID приложения, ошибка TLS-соединения, домен страницы товара не совпадает с доменом остальных товаров каталога, отсутствует/невалиден отложенный диплинк, не совпадают схемы диплинков Android/iOS, код валюты отличается между полями цены. Полный отчёт со списком проблемных товаров скачивается кнопкой «Скачать полный отчёт».

### История загрузок
Источник: `general/ecomm/ecomm_interface/ecomm_history`. Статусы: зелёный (успешно), жёлтый (загружен с ошибками — обработана только часть), красный (не удалось загрузить — критическая ошибка, например файл недоступен по URL). Принудительный повторный импорт — кнопка «Проверить снова», не дожидаясь заданного периода обновления. Замена/добавление файла — на вкладках «История загрузок» либо «Товары», с выбором режима «обновить каталог» или «заменить каталог».

### События (источники данных) и архивация товаров
Источник: `general/ecomm/ecomm_interface/ecomm_events`, `.../ecomm_goods`. Каталог обязательно нужно связать с источником данных — пикселем (для сайта) или мобильным приложением (для трекера), иначе динамическая реклама не соберёт аудиторию. На графике событий видно: сколько товаров пришло в событиях и сколько из них нашлось в каталоге — низкий процент совпадения чаще всего означает, что вместо реального ID товара передаётся строка `'VALUE'`. Товары можно архивировать/разархивировать — архивные исчезают из всех активных кампаний и групп, где присутствовали.

### Доступы
Каталог и группы товаров можно расшарить на другие рекламные кабинеты (по ID кабинета, через ссылку активации) с уровнем доступа «каталог + все группы» или «каталог + выбранные группы». Источник: `general/ecomm/feed_catalog/ecomm_catalog`.

### Массовое управление позициями через API
Для крупных каталогов (сотни тысяч позиций, частые изменения ассортимента) — методы `OfferBatchTaskCreate`/`OfferBatchTaskDetail` позволяют создавать/обновлять/удалять позиции одним HTTP-запросом и получать детальную информацию об ошибках валидации. [MCP]

## [UI] Маркетплейсы: подключение каталога

Источник: `general/ecomm/feed_catalog/ecomm_catalog_mp`, `general/ecomm/feed_campaign_marketplace`. Подключение всегда делается через кабинет продавца на стороне маркетплейса — сгенерировать ключ доступа руками нельзя через API VK.

| Маркетплейс | Что вводится в VK Рекламе | Где получить в кабинете продавца | Особенности |
|---|---|---|---|
| **Ozon** | Ссылка на страницу продавца, Client ID (обычно подставляется автоматически), API key | Seller → Настройки → Seller API → «Сгенерировать ключ», тип токена **«Product read-only»** (или «Товары») | — |
| **Wildberries** | Ссылка на магазин, API key | Профиль → Настройки → «Доступ к новому API», категории «Контент», «Цены и скидки», «Статистика» | **Срок действия ключа — 180 дней**, после истечения нужно перевыпустить и обновить в настройках каталога VK Рекламы |
| **AliExpress Россия** | Ссылка на магазин, токен API | Аккаунт → Токены API → «Создать токен» | — |
| **Яндекс.Маркет** | Ссылка на магазин | Авторизация в partner.market.yandex.ru → «Предоставить доступ» (OAuth) → выбор магазина из списка | Доступ выдаётся через OAuth, не через статичный ключ |

Если товар заканчивается на маркетплейсе, он автоматически пропадает из показа рекламы; новые позиции подтягиваются на очередном обновлении каталога.

### Нюанс: ретаргетинг маркетплейсов — только по кликам
У VK Рекламы нет доступа к внутренним событиям маркетплейса (просмотры/корзина/покупки там не видны) — для типа «Динамический ретаргетинг» аудитория строится **только по кликам** пользователей на объявления в предыдущей кампании «Привлечение потенциальных клиентов». Поэтому сначала обязательно запускается кампания на привлечение, и только затем — ретаргетинг на её кликнувших. Условие ретаргетинга — период учёта кликов (например, «от 0 до 30 дней назад»).

### UTM-метки для аналитики внешнего трафика
Реклама с маркетплейсов работает по моделям CPM/CPC — конверсии внутри маркетплейса напрямую в дашборде VK Рекламы не видны, нужна ручная аналитика через UTM:
- **AliExpress, Яндекс.Маркет** — ориентируются на CTR/CPC в самой VK Рекламе, отдельного шаблона меток нет.
- **Ozon** — метки создаются в кабинете продавца (Продвижение → Трафареты/Продвижение в поиске → Внешний трафик → «Создать ссылки»), затем вставляются в блок «Параметры URL» группы объявлений с опцией «Добавлять UTM-метки вручную».
- **Wildberries** — шаблон меток фиксированный: `utm_source=vk_ads&utm_campaign=<ID_продавца>-id-{{campaign_id}}&utm_content={{banner_id}}`, где `<ID_продавца>` — последние цифры в ссылке вида `wildberries.ru/seller/785935`.

Также при желании можно включить «Автоматически удалять UTM-метки» на уровне каталога, чтобы сторонние метки в фиде не конфликтовали с метками VK Рекламы. Источник: `general/ecomm/feed_catalog/ecomm_catalog`.

## Full Stream Attribution (FSA) — кратко

Источник: `general/ecomm/dyn_ret/fsa`. Технология прямой передачи событий с сайта/приложения напрямую в рекламную систему VK по номеру телефона (хэш MD5/SHA-256), в обход пикселя/трекера-посредника — **дополняет**, а не заменяет обычные события ретаргетинга.

Ключевые цифры: события доходят до профиля пользователя за **до 90 секунд** (vs 4–6 часов при стандартной интеграции); для подключения желательна уникальная аудитория сайта/приложения от **500 000 пользователей/мес**; окно атрибуции для `purchase` по умолчанию **7 дней** (настраивается по запросу).

Технически — партнёр отправляет POST на `https://fsa.mail.ru/fsa` (или батчами до 1 МБ на `/fsa-batch`) с полями `phone_md5`/`phone_sha256`, `platform`, `customEventName` (`viewOffer`/`addToCart`/`addToWishlist`/`purchase`), `productId`, `eventTimestamp` (Unix UTC). Подключение — через персонального менеджера VK; требует отдельного рекламного кабинета, привязанного пикселя/приложения и загруженного каталога, плюс включённого при создании кампании тумблера «Атрибуция по номеру телефона (FSA)». Это интеграция уровня бэкенд-разработки на стороне партнёра, не самостоятельная UI-настройка.

## Чек-лист «каталог готов к запуску»

- [ ] Фид соответствует лимитам: ≤8 ГБ по ссылке / ≤100 МБ файлом, ≤4 млн товаров, UTF-8/Windows-1251, без «сырых» HTML-тегов в тексте
- [ ] Обязательные поля вертикали заполнены (для товаров: `id`, `title`, `price`, `link`, `image_link`, `brand`); изображения квадратные, 300–6000px, без водяных знаков
- [ ] Минимум 3 товара в фиде помечены «в наличии» (`availability=True`) — иначе каталог не пройдёт диагностику
- [ ] Каталог создан в Центре коммерции (фид по ссылке / сообщество ВК / маркетплейс / файл) и привязан к источнику событий — пикселю или мобильному приложению
- [ ] На сайте настроены три обязательных события `_tmr.push`: `viewProduct`, `addToCart`, `purchase` (+ опционально `addToWishlist`), все с параметром `product_id` в формате, совпадающем с полем `id` фида
- [ ] Для приложения — трекер (MyTracker/Adjust/AppsFlyer/AppMetrica/Branch) настроен, категории событий проставлены, параметр ID товара определён
- [ ] Вкладка «Диагностика» — 0 критических ошибок; «События» — процент совпадения ID товаров высокий (не «VALUE» вместо реального ID)
- [ ] Группы товаров созданы под нужную сегментацию (если кампаний/аудиторий несколько), с учётом лимита 1000 товаров на группу
- [ ] Для маркетплейсов — API-ключ действителен (Wildberries: проверить срок 180 дней), UTM-шаблон настроен, зона доставки товаров соответствует гео таргетинга кампании
- [ ] Для динамического ретаргетинга маркетплейса — предварительно прогнана кампания «Привлечение потенциальных клиентов» для накопления кликов
- [ ] Выбран верный тип кампании (Привлечение / Динамический ретаргетинг) и, если нужно, включена FSA
