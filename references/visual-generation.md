# VK Ads — генерация визуала через AI (M1)

Модуль M1 — генератор статичных картинок через OpenAI Images API. Покрывает 5 типов креативов из `creatives.json`.

## Когда использовать

- После Шага 10 (создан `creatives.json` с текстами).
- Перед Шагом 11 (залив в кабинет).
- Когда нет дизайнера / нет времени на ручную верстку.

## Когда НЕ использовать

- **UI-скриншоты продукта** — AI генерит ненадёжно. Запрашивай реальные скрины от клиента или используй Figma mockup.
- **Видео** — это модуль M2 (отдельный pipeline через Veo / Kling / Runway).
- **Лица реальных людей в UGC** — для UGC нужны реальные люди (актёры или клиенты), AI распознают как «искусственные».

## Архитектура

```
scripts/
├── generate_creative_images.py   ← главный скрипт (CLI)
├── prompt_templates.py            ← 5 шаблонов под типы креативов
└── brand_defaults.json            ← defaults цветов и стиля
```

В рабочей папке кампании:
```
vk-campaign-<slug>/
├── brand.json                     ← (опционально) переопределение бренда
└── assets/
    ├── images/                    ← сгенерированные картинки
    ├── prompts/                   ← сохранённые промпты (для аудита)
    └── generation_log.json        ← лог запуска
```

## 5 типов креативов

| Тип | Когда применяется | Размер OpenAI → VK |
|---|---|---|
| `ebook_cover` | Обложка PDF lead magnet | 1024×1536 → 1080×1350 (4:5) |
| `pain_split` | Split-screen «до/после» | 1024×1536 → 1080×1350 (4:5) |
| `abstract_brand` | Брендовая композиция с текстом | 1024×1024 → 1080×1080 (1:1) |
| `carousel_card` | Карточка карусели | 1024×1024 → 1080×1080 (1:1) |
| `ui_mockup` | UI-скриншот — **placeholder, нужен реальный** | 1024×1024 → 1080×1080 |

## Автоопределение типа

`detect_creative_type(creative)` смотрит на `name`, `format`, `image_or_video`:

- `name` содержит `ebook` → `ebook_cover`
- `name` содержит `pain` или `image_or_video` содержит `split` → `pain_split`
- `name` содержит `nocode` (карусель UI шагов) → `ui_mockup`
- `format` = `carousel` → `carousel_card`
- `image_or_video` содержит `ui` / `screenshot` → `ui_mockup`
- иначе → `abstract_brand`

Стоимость на 2026: gpt-image-1 high quality ~$0.04-0.08 за картинку. Dall-E 3 hd ~$0.08.

### Шаг 3. Полный прогон

```bash
python -m scripts.generate_creative_images \
  --workspace C:\Users\ptica\Documents\Claude\Projects\FB\vk-campaign-<slug>
```

Для 7 креативов с одной каруселью на 4 карточки = ~10 картинок ≈ $0.40-0.80.

### Шаг 4. Ревью

Открыть `assets/images/`, посмотреть результат. Если что-то не понравилось:

```bash

  --workspace ... --only cr_ebook_p1 --force
```

Или вручную поменять промпт в `assets/prompts/<name>.txt` и сделать `--force`.

## Какая модель лучше

| Модель | Плюсы | Минусы | Когда брать |
|---|---|---|---|
| **gpt-image-1** | Хорошо рендерит текст и брендинг, понимает «layout» | Дороже, медленнее | Дефолт. Для eBook обложек с заголовками, абстрактных композиций с typography. |
| **dall-e-3** | Дешевле, быстрее | Хуже с текстом, может перевирать буквы | Если бюджет важнее, или для split-screen где меньше типографики. |

## Промпт-инженерия (что важно)

### Что работает
- **Указывать стилевые ориентиры** («Notion eBook cover», «Linear documentation style»)
- **Конкретные цвета в HEX** — модель понимает
- **«No people. No realistic photos.»** — если хочешь vector/flat
- **Aspect ratio** в промпте — даже если задаёшь через `size`, дублируй в тексте
- **«DO NOT include»** блок — модель его слушает

### Что НЕ работает
- Названия реальных конкурирующих брендов в промпте («like Notion but better») — модель боится копирайта
- Точное расположение всех элементов — модель не пиксель-перфект
- Сложные UI mockup — даже gpt-image-1 ломается на интерфейсах
- Картинки с >15 словами текста — текст становится мусором

## Постпроцессинг (PIL)

OpenAI не поддерживает 1080×1080 / 1080×1350 нативно. Скрипт ресайзит и центральный crop через PIL:

- Сначала генерим в ближайшем поддерживаемом размере (1024×1024 / 1024×1536)
- Потом PIL делает crop+resize до VK target (1080×1080 / 1080×1350)
- Сохраняем в PNG

Если PIL не установлен — картинка остаётся в исходном размере, скрипт выдаёт WARN.

## Лимиты и rate-limits

- OpenAI Tier 1: 5 image/min. Скрипт делает паузу 1.5 сек между генерациями.
- Tier 2+: 50 image/min — можно ускорить (убрать `time.sleep`).
- Размер ответа base64: ~1-3 MB на картинку — следи за памятью при больших партиях.

## Что делать с UI mockup креативами

Если в `creatives.json` есть UI-скриншоты (cr_nocode_p2, cr_teams_marketing, etc):

1. **Лучший путь:** запросить у клиента реальные high-res скриншоты (минимум 2160×2160) — они в любом случае лучше любого AI mockup.
2. **Если нет:** использовать Figma + AI плагин (Figma AI, Magician) для mockup.
3. **Крайний случай:** использовать AI-generated UI mockup из скрипта — но предупреждать что качество низкое, продукт может выглядеть «как сгенерированный AI».

В логе скрипт пометит такие креативы как `needs_real_screenshot` — обратись к клиенту.

## Безопасные зоны креатива (safe zones) — обязательно при генерации [MCP]

VK накладывает на креатив служебные элементы (метка «Реклама», счётчик карусели, дисклеймер), которые перекрывают край изображения на разных плейсментах. Наш внешний генератор обязан держать текст/лого/ключевой объект внутри безопасных зон, иначе они окажутся под перекрытием. Ориентиры (источник: features/safe):

- Лента/посты: не размещать важное в верхних 10% и правых 10-15% (там метка «Реклама» и счётчик карусели).
- Нативные баннеры: верхние 10% (метка), для видео — верхние/нижние 10%.
- In-stream / out-stream видео: верхние 15%, нижние 25%.
- Клипы / истории (9:16): по 15-20% сверху и снизу; при обрезке в ленте клипов — ещё по 10% слева/справа.
- Дисклеймер занимает ~10% площади баннера / ~15% площади изображения — оставлять под него место.
- HTML5-баннеры: свободные зоны 80×30px (левый верх) и 40×40px (правый верх).

При формировании промптов в `scripts/generate_creative_images.py` закладывать отступы под эти зоны и не ставить текст/логотип впритык к краям.
