# План правок: приведение `vk-ads-manager` в соответствие с хостовым MCP

**Скилл:** `vk-ads-manager` (репозиторий `ai-hub-open/vk-ads-manager`)
**MCP:** `https://vkads-mcp.aihub.click.ru/mcp` (`ai-hub-open/vk-ads-mcp`)
**Дата сверки:** 26.08.2026
**Источник истины:** живой тул-сёрфейс сервера, снятый в сессии 26.08.2026 — **45 инструментов**, не 48.

Сверка выполнена вызовами в реальный кабинет (`vkads_486007@vk@14029134`, режим click.ru). Все расхождения ниже подтверждены либо успешным вызовом, либо отсутствием инструмента в сёрфейсе.

---

## 0. TL;DR для исполнителя

Скилл ссылается на **5 несуществующих инструментов** и не знает о **2 существующих**. Один из несуществующих (`vk_ads_banners_create`) стоит в инструкции по заливу кампании — из-за него в кабинете уже лежат 4 группы объявлений без единого баннера.

Правки только документационные: `.md` файлы скилла. Код (`scripts/`) в этом плане **не трогаем** — см. раздел 5.

```markdown
### 🚨 Объявление нельзя создать отдельным вызовом

В API нет `POST /banners`. Объявления создаются **только** вложенным массивом внутри группы:

`vk_ads_campaigns_create(payload={..., "banners": [{...}, {...}]})`

Либо целиком атомарно: `vk_ads_ad_plans_create(payload={..., "campaigns": [{..., "banners": [...]}]})` —
`ad_plans_create` принимает вложенные `campaigns`, а `campaigns_create` принимает вложенные `banners`.

Создать группу, а потом «долить» в неё объявления — **нельзя**. Группа без баннеров
уходит в `status: blocked` с issue `NO_BANNERS_WITH_ACTIVE_STATUS` и остаётся мёртвой.

### `campaigns` и `ad_groups` — одна сущность

`vk_ads_campaigns_list` и `vk_ads_ad_groups_list` возвращают **идентичный результат** —
это не два уровня иерархии, а два имени одного ресурса. Иерархия трёхуровневая:
`ad_plan` → `campaign` (= `ad_group`) → `banner`.

По умолчанию используй `vk_ads_campaigns_*`. Набор `vk_ads_ad_groups_*` оставлен
для совместимости; исключение — `vk_ads_ad_groups_get`, он удобен тем, что отдаёт
`issues` (диагностика, почему группа не крутится).
```

### 2.5. Требования к ссылкам на изображения (новое поведение)

**Зачем.** На хостовом MCP локальные файлы недоступны, `vk_ads_content_upload_image`

```markdown
## Требования к ссылкам на изображения от клиента

Скилл загружает креативы в VK по URL. Ссылка обязана удовлетворять **всем** пунктам:

| # | Требование | Как проверить |
|---|---|---|
| 1 | **Прямая ссылка на файл**, а не на страницу просмотрщика | Открыть в режиме инкогнито: должна показаться голая картинка на пустом фоне, без интерфейса, кнопок «Скачать» и превью-панели |
| 2 | **Публичный доступ без авторизации** и без срока действия | Открывается в инкогнито у постороннего человека и завтра тоже |
| 3 | **Формат JPG или PNG** | Расширение в URL либо заголовок `Content-Type: image/jpeg` / `image/png` |
| 4 | **Разрешение под формат размещения** — см. таблицы форматов выше: 1:1 — минимум 600×600 (рекомендуется 1080×1080); 16:9 — 1080×607; 4:5 — 1080×1350 | Свойства файла |
| 5 | **Скриншоты интерфейса продукта — минимум 2160×2160** | Retina-скрин или экспорт из макета, не кроп с обычного монитора |
| 6 | **Одна ссылка = одно изображение**, с подписью, к какому креативу или сегменту относится | — |

### Что НЕ подходит (частые случаи)

- ❌ Шаренные ссылки **Google Drive, Яндекс.Диск, Dropbox, OneDrive** — они отдают
  HTML-страницу просмотрщика, а не файл. Нужен либо прямой файловый URL, либо
  выкладка на любой публичный хостинг.
- ❌ Ссылки на **папку** вместо конкретного файла.
- ❌ Ссылки с **временным токеном** в query-параметрах (`?token=`, `?expires=`) —
  протухнут между согласованием и заливом.
- ❌ Адреса во **внутренней сети** (`localhost`, `192.168.*`, корпоративный
  файлообменник за VPN) — сервер загрузки режет их SSRF-защитой.
- ❌ **Превью и миниатюры** из выдачи или из письма — почти всегда меньше минимума по п.4.

### Куда выкладывать, если прямой ссылки нет

Рекомендуемый вариант — **https://imgbb.com** <cite index="4-1">(бесплатный хостинг, загрузка без регистрации, выдаёт прямые ссылки)</cite>. Порядок:

1. Открыть imgbb.com, перетащить файл. Аккаунт не нужен. <cite index="1-1">Лимит — 32 МБ на файл, принимает JPG, PNG, GIF, BMP</cite>.
2. **В настройке автоудаления выбрать «Don't autodelete».** <cite index="1-1">По умолчанию предлагается удаление через час, день или месяц</cite> — с таким сроком ссылка умрёт между согласованием и заливом, а на активной кампании креатив просто отвалится.
3. **Не пользоваться опцией resize на экране загрузки** — она уронит разрешение ниже минимума из таблицы выше.
4. После загрузки скопировать **«Direct link»**, а не «Viewer link». <cite index="2-1">imgbb предлагает оба варианта</cite>, и это ровно та ошибка, о которой п.1 таблицы: правильная ссылка выглядит как `https://i.ibb.co/XXXXXXX/file.png` и заканчивается расширением файла; `https://ibb.co/XXXXXXX` — это страница просмотрщика, файл по ней не скачается.

⚠️ **imgbb — публичный хостинг без пароля.** Всё, что туда выложено, доступно любому по ссылке. Для скриншотов непубличного интерфейса, préview неанонсированного продукта или чего-либо под NDA — согласуй с клиентом отдельно или используй его собственный хостинг / CDN.

Альтернативы, если клиент не хочет imgbb: любой его собственный публичный CDN, S3-бакет с public-read, или картинка, уже выложенная на сайте клиента (тогда ссылка берётся прямо оттуда).
```

## 3. Открытый вопрос — НЕ чинить вслепую

`vk-ads-launcher/scripts/vk_ads_client.py:150` содержит `create_banner()`, который делает
`POST banners.json` с `ad_group_id` в payload. То есть **launcher утверждает, что отдельное
создание баннера существует**, а MCP утверждает, что нет.

Один из двух артефактов неправ. Это не решается чтением кода — нужен один пробный
write-вызов в кабинет (создать баннер в существующей группе и сразу удалить).

**Что делать Cursor'у:** ничего. Не приводить launcher к MCP и не «чинить» его
`create_banner`. Просто добавить в `vk-ads-launcher/references/api_quirks.md` пометку:

```markdown
> ⚠️ Не сверено: `create_banner()` (`POST banners.json`) конфликтует с описанием
> vk-ads-mcp, где сказано, что отдельного создания объявления в API нет.
> Требуется проверка живым вызовом. До проверки предпочитай создание баннеров
> вложенным массивом внутри группы.
```
